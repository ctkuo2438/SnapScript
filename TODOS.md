## TODO 1: Rate limiting on Streamlit Cloud deployment

**What:** Add session-based rate limiting in `web_interface.py`.
**Why:** A public Streamlit deployment with no rate limiting lets one user spam the
Generate & Run button repeatedly, exhausting the API key budget. Even with user-supplied
API keys, the behavior creates confusion and bad first impressions.
**How to apply:**
- `st.session_state['run_count']` — max 10 runs per session
- 5-second cooldown between runs (disable button after each run, re-enable after delay)
- Show run count remaining: "7 of 10 runs used this session"
**Where to start:** `src/snapscript/interfaces/web.py`, around the Generate & Run button handler.
**Depends on:** web_interface.py being written (Day 11+).
**Priority:** Must-have before Streamlit Cloud launch.

## TODO 2: Prompt engineering iteration budget

**What:** Reserve Days 8-10 for dedicated system prompt iteration after the basic pipeline
is wired up (Day 7) and before Streamlit work begins (Day 11).
**Why:** The hardest part of SnapScript is getting Claude to reliably generate correct,
runnable pandas code across varied task descriptions. This work is invisible in the
implementation plan but determines whether the 10 CLI gate tasks pass. Without dedicated
time, it gets squeezed by implementation pressure.
**How to apply:**
1. Day 7: pipeline functional, all 10 CLI gate tests runnable.
2. Days 8-10: run all 10 tasks, record failure modes, iterate `prompts/system.txt`.
3. Gate to move to Streamlit: 8/10 CLI tasks pass on first attempt (no retry needed).
4. Document every prompt change and what it fixed — this becomes the prompt changelog.
**Where to start:** `src/snapscript/prompts/system.txt` — the system prompt is the product.
**Depends on:** CLI pipeline functional.
**Priority:** Gate condition for starting Streamlit work.

## TODO 3 (completed during /plan-eng-review): Architecture decisions

The following decisions were made during plan review and incorporated into the design doc.
They are listed here for traceability:

- **PATH injection**: `sandbox_executor` writes `_snapscript_paths.py` to tempdir.
  Generated scripts use `from _snapscript_paths import INPUT_PATH, OUTPUT_PATH`.
  No str.replace() on generated code.

- **Output validation**: `sandbox_executor` reads first row of output file after execution.
  Empty or unreadable output → `ExecutionResult(success=False)`.

- **Model escalation**: `code_generator.generate(prompt, model=None)` accepts optional
  model override. `retry_handler` passes `config.fallback_model` on attempt 2.

- **Prompt injection**: `schema_inspector` truncates column names to 100 chars.
  `prompt_builder` wraps schema section in `<schema>...</schema>` delimiters.

- **open() safety**: Removed from `BLOCKED_CALLS`. Added AST check for `open()` calls
  with literal string arguments containing `/` (absolute path) or `..` (traversal).

- **Deployment**: GitHub Actions (pytest gate) → Streamlit Cloud webhook. Not manual deploy.

- **Memory/chunked processing**: schema_inspector reads nrows=1000 (no chunked reading
  needed there). System prompt instructs Claude to prefer chunked processing for
  large-file transformation tasks where applicable.

- **Timeline**: 30 days, not 8 days. Day 1-10: CLI pipeline. Days 8-10: prompt iteration.
  Day 11-25: Streamlit. Day 26-30: user observation.
